Workflow

How a part gets from an idea onto the robot

Not a rule, but it is the order that wastes the least material and the least time.

  1. Step 1

    Read the manual, then argue

    Strategy first, against what the game actually scores. Arguing on paper is free. Arguing in aluminium is not.

  2. Step 2

    Model it in Onshape

    CAD the mechanism before anything gets cut or printed. Onshape runs in a browser and is free for students, so there is nothing to install and nothing to lose.

  3. Step 3

    Build it

    Cut, print, assemble, wire. Check the inventory before ordering anything, because we usually already own it.

  4. Step 4

    Code it in VS Code

    The robot code is our copy of the FTC SDK, on GitHub. Clone it, open the folder in VS Code, and commit as you go: small commits, real messages, on a branch rather than straight onto main.

  5. Step 5

    Test it, then write it down

    Drive it, break it, measure it. Then put the decision and the numbers in the engineering notebook in the team Drive while you still remember why you made them. Judges read that notebook, and it is how the Inspire Award gets won.

Ground rules

Four things that keep this working

  • CAD before you cut. Even a rough model catches the collision you were about to build.
  • Commit before you leave. Work that exists on one laptop does not exist.
  • Write it up the same day. The notebook gets written while you remember, not the night before judging.
  • Ask in Discord. Somebody has already hit your error. Do not lose an afternoon to it alone.

New to all of this? Nobody expects you to know it on day one. Start at step 3 and pick up the rest standing next to someone doing it.

Software

What to install

All free. Onshape needs no install at all, and you do not need every one of these on day one.

Onshape CAD, in the browser, free for students. The whole team can be in one document at once, so the person building a part is looking at the same thing as the person who drew it. Open Visual Studio Code Where we write the robot code. Free, quick to start, and it handles Java and Git without a fight. Open FTC SDK (FtcRobotController) The official starting point for robot code. Everything we write sits on top of this repository. Open Git Version control. Install it once and nobody loses a season of work to a dead laptop. Open GitHub Desktop Optional. Does the commit, pull, and push part with buttons, if the command line is not your thing yet. Open Android Studio The heavyweight option FIRST documents. Big download, but it builds the Robot Controller app and debugs on the device. Open REV Hardware Client Updates firmware on the Control Hub and the motors. Windows only, and you only need it now and then. Open
